# 英语模块内容与页面升级

## 范围与来源

主应用采用独立静态站的英语页面组织方式，保留两套前端各自的运行和构建边界。静态站不在主应用运行时提供文件或数据库依赖。

| 内容 | 当前来源 |
| --- | --- |
| 词汇目录 | 18 个一级分类、167 个二级主题 |
| 来源词条 | 7,053 条；1,750 条已确认、1,163 条待复核、4,140 条未分类 |
| 语法 | 42 个课节 |
| 世界目录 | 16 个一级分类、144 个主题 |
| 世界、随笔文章 | 均为 0 篇已发布文章，显示真实空状态 |

世界、随笔替代原阅读和写作公开入口；旧地址兼容跳转，保留查询参数和锚点。旧词汇主题和搜索中的未分类词条可通过新词卡页面查看。既有学习计划、记忆状态、发音和私人草稿的服务与所有权规则保持兼容。

## 后台与数据约束

- 首页文案可编辑，数量从真实内容统计；不再提供与当前公开首页脱节的阶段设置。
- 词汇编辑与分类修改使用同一事务和乐观锁。待复核、未分类词条完整保留，但不进入已确认主题目录。新增词条进入未分类队列。
- 世界文章继续执行正文、版权与发布校验。随笔继续执行所有者、完成状态、版本和公开资格校验，普通账户不能使用新的后台管理入口。
- 新接口沿用 Session、CSRF 和既有英语权限。请求字段与查询结果字段分开，禁止把只读响应对象作为写入命令提交。
- 仅新增 `V2_048` 结构迁移；内容对齐由显式维护操作完成，不在启动时撤下或删除内容。

本次本机旧公开阅读和写作示例各 144 篇被撤回公开状态，保留正文、作者、版权、版本和相关历史。所有单词继续使用原 ID。整库备份、恢复演练及校验材料保存在项目内部的 `history/`；缓存和临时浏览器材料保存在 `.local/`。

## 接口入口

| 用途 | 路径 |
| --- | --- |
| 概览 | `GET /api/public/english/library/overview` |
| 两级目录及数量 | `GET /api/public/english/library/{vocabulary\|world}/{taxonomy\|counts}` |
| 词汇筛选 | `GET /api/public/english/library/vocabulary/words` |
| 词条与分类编辑 | `PUT /api/admin/english/library/vocabulary/{id}` |
| 世界文章 | `/api/public/english/world/articles`、`/api/admin/english/world/articles` |
| 随笔与公开筛选 | `GET /api/public/english/essays`、`GET /api/public/english/essays/facets` |
| 随笔后台与发布 | `/api/admin/english/essays`、`/api/admin/english/essays/publication` |

词汇支持 `q`、`category`、`topic`、`status`、`theme`、`page`、`size`；分页每页最多 100 条。主题必须属于当前父分类，非法路径返回 404。编辑使用 `migrationStatus`、`migrationReason`、`topicCodes`、`rowVersion` 和可选的可编辑 `word` 字段。已确认记录至少关联一个有效二级主题，版本冲突返回 409。

随笔支持标题、标签、文体、月份及分页组合筛选，每页最多 50 条。列表、侧栏统计和详情均排除私人、未完成、无公开资格或已删除的内容。

## 同步与恢复

1. `node tools/export-static-english.mjs` 导出当前来源，审核目录和正文。
2. 在独立测试库执行结构迁移，并恢复真实备份演练内容对齐。
3. `python tools/sync-static-english.py --config <项目内配置>` 默认预览并回滚；增加 `--apply` 才在整库备份后提交。
4. 使用既有维护入口重建搜索和 SEO 投影，再核对公开结果及学习数据。

正文转换逐节核对可见文本；当前 42 节均无文字丢失。来源增加世界或随笔文章后，同步脚本会停止，要求先审查版权及作者归属；日常写作与发布使用正常后台，不需要重新执行来源替换。

结构迁移与内容对齐分别留有整库备份；失败时保留错误、备份和待处理材料，不覆盖当前内容或自动回退用户后续编辑。GitHub 同步和本地运行均不代表服务器部署。
