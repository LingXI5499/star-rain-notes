- 根因：`frontend/src/modules/blog/pages/admin/BlogEditorPage.vue` 的确认只在 `leaveEditor`，不在路由生命周期。

### SR-002｜提交与持久化快照

- 状态：CONFIRMED；优先级 P0；结果 FIXED。
- 复现：发送正文 A，等待响应时输入 B；旧实现 markSaved 把 B 也确认。只保存正文会错误确认未提交标题。
- 根因：`saveBody → markSaved` 和 `saveMeta → markMetaSaved` 都读取异步响应时的可变表单；saveAll 在第二步重新读取正文。
- 方案：请求前一次捕获元数据/标签/正文/ID/代数；分别维护服务端确认的元数据和正文；保存文章复用同一提交快照。
- 不改变 Slug 和接口；标签名称只在当前选择未变时转换为 ID；正文响应更新引用详情，不覆盖输入。
- 创建成功但正文失败保留草稿与正文并显示部分成功。传输或 5xx 错误显示“结果尚未确认”，禁止自动重放；已有文章可只读核实服务端结果，再由用户保存仍有差异的输入。创建结果不明时需在列表核实，不能盲目重复创建。
- 测试：同上；延迟响应继续编辑、字段独立保存、saveAll 捕获、部分成功、请求未完成切文章、超时只读核实、卸载后响应。
- 修复前 12 用例中 9 失败；修复后 18 新用例全部通过。全套 53 文件、262 通过、0 失败/跳过（18.88s）；构建通过（6.28s）。
- 剩余：现有博客 API 无版本冲突契约，多客户端同时编辑仍采用原有语义；本轮没有擅自引入版本字段。创建超时无法从现有 API 获得幂等操作结果。
