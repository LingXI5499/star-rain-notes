# Markdown 编辑器 V3 实施报告

日期：2026-10-14。需求来源：用户提供的《md文档编辑.md》。用户补充约束优先：Markdown 支持导入和导出，PDF、Word 仅导出。

基准：GitHub main `c6ed63255c49b4fc32aeaac939101e728c68f5bc`；本地开发分支 `codex/markdown-editor-v3`。本轮完成 A–D 的代码实现与自动化检查，人工验收尚未完成，不能解释为全部需求验收通过。没有执行生产部署，也没有推送或合并本轮改动。

## 2026-10-15 菜单与全屏修订

按用户截图反馈，将多排工具按钮与底部图片入口收拢为单行「文件、编辑、段落、格式、视图、主题、帮助」菜单。工具面板按需展开，字数/行数保留在底部。上传图片用于插入本地素材，媒体库用于复用已有素材，两者位于「格式」菜单，上传权限与 PROTECTED 默认值保持原有约束。

全屏改为将整个编辑器通过 Teleport 移到 body，保留 Vditor 实例、正文 DOM、光标与内部滚动位置。编辑区按视口可用高度布局，退出恢复外层滚动；背景暂时 inert，路由卸载或文档切换释放页面状态。使用 Vditor 的公开 Escape 回调处理其内部按键拦截，提示或菜单先关闭，再退出全屏。编辑器主题同步控制台主题按钮且不执行圆形切换动画。

同时发现选区浮动栏会受原页面堆叠与裁切影响，偶尔被顶栏遮挡、点击落到其他区域。选区浮动栏、斜杠命令和菜单弹层统一移到 body，按各实例 DOM 引用处理外部点击与监听清理。

新前端包：`releases/editor-menu-fullscreen-20261015/dist.zip`。这次只修改前端，没有新 JAR、YAML 或数据库迁移；完整替换前端 dist 内容即可。旧包保留在原目录，可用于回滚。本轮没有推送远程或部署生产。

本次全量单元测试 390 项与全量浏览器 30 项通过；弹层与全屏四组专项连续三轮、共 12 次通过。详细环境、测试边界与本机日志见验收记录中的 2026-10-15 补充章节。

## 技术选择与边界

保留 Vditor 3.11.3 与原 `v-model` / `getMarkdown()` 接口。版本相关原生工具栏选择器集中在 `commands/vditorAdapter.js`，正文修改使用 Vditor 公开 API；没有调用库并不存在的 `setHeadingLevel()` 或原生 `setMode()`。源码结构通过 Markdown token 与受保护行范围定位，不批量改写复杂块。新增模块随编辑器路由加载。

阅读预览复用现有 `renderMarkdownDocument()`、DOMPurify、代码组增强和 MathJax；没有修改公开 Markdown 解析器或后端 SEO 快照。图片尺寸仍为 normal/wide/full；上传串行、使用真实上传进度或不定进度，默认 PROTECTED，不自动公开。切换身份/文档/字段时中止旧上传和清除失败文件。

所有 MarkdownEditor 调用页面均显式提供账号、模块、文档、字段、服务器基线和版本：博客、作品正文/区块、教程章节/知识卡片/问题、英语写作/阅读双语字段、语法课程/课时、英语总览、个人介绍。新文档使用浏览器会话 UUID，获得服务器 ID 后原子迁移；作品区块与中英文分别隔离。

本地恢复在停止输入 1.8 秒后及页面隐藏时尝试备份，每字段 3 个恢复点、每账号最多 50 个字段，达到上限明确报错而不删除唯一脏副本。记录结构版本、原文、基线、服务器版本、SHA-256 与时间；这些元数据不等于加密。账号不明确时不持久化。恢复先展示两个版本原文，确认后只改变本地输入。服务器 409/428/超时不会清空恢复点；只有已确认的提交快照与当前内容一致时才清理。英语写作的恢复/导入会暂停自动保存，必须点击「确认保存恢复稿」。退出前核对恢复点并明确确认清理，旧回包不会重建已清理的草稿。

质量检查覆盖 MD001–MD009，包括标题跨级、替代文本、空/非法链接、围栏/公式闭合、表格列数、长段落、重复标题、受保护媒体、代码组完整性和标签匹配。只展示建议，不改写正文或替代后端发布权限。面板开启后防抖检查；50k 及以上在 worker 中计算，关闭或身份变化时释放旧任务。围栏教学样例不作为真实正文检查。

MD 导入限 UTF-8 的 .md/.markdown、2 MiB，拒绝非法编码和二进制。确认前展示字符/标题数与两份原文，支持替换/追加；确认期间正文变化则拒绝导入。行尾规范化为 LF，导入不自动提交服务器。导出从编辑器读取最新正文。

Word 使用 `docx@9.11.0` 动态生成真正的 OOXML ZIP，包含标题、行内格式、列表、表格、全部代码组面板与正文；公式保留 TeX，图片保留替代文本和链接。PDF 使用隔离页面与打印样式，复用净化后的阅读 HTML/MathJax，并打印全部代码组面板；用户在浏览器打印对话框选择「另存为 PDF」。取消打印不是生成成功。PDF/Word 均无导入入口。

依赖变化：增加运行时 `docx@9.11.0` 和测试用 `fake-indexeddb@6.2.5`，其余核心编辑器/解析器版本保持锁定。Word 导出依赖的公开第三方声明随前端制品放入 `legal/editor-word-third-party-notices.txt`。

## 已验证的限制与降级

Vditor 原生 SV→IR 转换可能截断表格单元格中的带管道符行内代码，已在真实浏览器复现。适配器比较转换前后语义，失败则恢复原文并提示原视图/阅读预览；原生模式菜单也受保护。普通内容三模式已验证，但不能宣称所有复杂语法都可自由切换。

超过 100,000 字符从原生 SV 启动，并限制其他大型编辑树，关闭源码同步预览；普通文档保持 IR 默认。减少光标移动时的全文复制，质量检查转入 worker。200k 原策略曾测得约 11 秒输入延迟、约 1 GB 堆内存，改动后约 1.9 秒、约 93 MB。该结果体现改善，100k/200k 仍有明显延迟，尚未达到普通文档流畅度；50k 单 worker 测得 138.1 ms，最终并行测得 199.7 ms，不能宣称稳定达到 150 ms 目标。详见验收记录。

多行段落、Setext 或跨复杂块标题转换明确拒绝；IR/WYSIWYG 跨段操作提示使用源码。表格修改优先支持 SV；重复 URL、引用式图片等无法可靠定位时提示直接编辑源码。DOCX 的公式/图片采用明确的源码/链接降级，尚未验证真实 Word/WPS 排版。物理键盘、真实中文 IME、移动触摸与 PDF 实际分页需要人工验收。
