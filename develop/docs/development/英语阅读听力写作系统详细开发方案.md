本文档定义星雨笔录英语模块中“阅读、听力、写作”三个剩余子系统的完整工程实施方案。内容覆盖：

- 分阶段开发任务、测试矩阵、验收标准和Git流程。

本文档不是概念草案，而是后续实现的工程规格。实现过程中如发现真实代码与本文冲突，应先记录差异、停止扩大修改范围，并由项目所有者确认后更新本文档，禁止开发者自行改变业务语义。

## 2. 当前系统基线与已知约束

### 2.1 已有模块

当前英语模块已经包含：

1. 英语总览：课程目标、当前阶段和路线说明。
2. 单词系统：主题、词条、音标、释义、词形、例句和全局记忆次数。
3. 语法系统：独立单课程、10个一级章节、42个课节、Markdown阅读和后台结构管理。
4. 英语管理工作台：固定展示单词、语法、阅读、写作、听力五个子系统。

阅读、听力、写作目前仅显示“建设中”，尚无对应业务表和接口。

### 2.2 技术栈

- 后端：Java 21、Spring Boot 3.5、Spring Security、MyBatis-Plus、JdbcTemplate、Flyway、MySQL 8。
- 前端：Vue 3、TypeScript、Vue Router、Element Plus、Vite、Vditor。
- 鉴权：服务端Session、CSRF Cookie/Header、单管理员账号。
- 媒体：本地文件存储，生产环境由Nginx提供 `/uploads/**` 静态资源。
- 当前数据库迁移最高版本：Flyway V8。

### 2.3 必须正视的现实限制

1. 当前只有管理员账号，没有普通学习者账号。
2. 当前媒体库只允许 `IMAGE` 和 `DOCUMENT`，不支持音频。
3. 当前全站搜索会分别查询各业务表并在JVM中聚合全部命中项，内容规模扩大后需要优化。
4. 当前单词的 `inflections` 是纯文本，无法承载派生词独立音标、CEFR等级和例句。
5. 文档只提供分类体系，没有提供真实阅读文章、音频文件、听力字幕、写作范文或写作课程正文。

### 2.4 本阶段确认的产品决策

1. 只导入分类、难度标准和必要字典，不虚构文章、音频、范文或教学正文。
2. 阅读、听力、写作使用独立业务表，不建立混合所有英语内容的万能表。
3. 三个系统共享标签、难度、练习、学习组合和学习记录能力。
4. 游客学习记录首先保存在浏览器；管理员个人记录可以同步服务端。
5. 本阶段不开发开放注册、邮箱验证、验证码、找回密码或多用户社交功能。
6. 自由写作第一版不使用AI自动评分，只提供客观统计、评分量表、自评清单和参考内容。
7. 音频第一版支持MP3、M4A和OGG，不支持WAV，不在服务器生成波形图。

## 3. 产品目标与非目标

### 3.1 产品目标

阅读系统应帮助学习者完成“理解句子—识别结构—推断观点”的能力递进。

听力系统应帮助学习者完成“识别语音—捕获信息—实时理解逻辑”的能力递进。

写作系统应帮助学习者完成“扩展句子—组织段落—建立衔接—控制风格”的能力递进。

三个系统最终形成以下闭环：

```text
同一主题与难度
    ↓
阅读输入 → 理解结构与词汇
    ↓
听力输入 → 识别真实语流
    ↓
写作输出 → 组织并生成表达
    ↓
练习结果 → 薄弱点 → 下次复习与相关推荐
```

### 3.2 非目标

本阶段明确不包含：

- 开放注册和用户社区；
- 在线付费、订单、会员等级；
- 实时语音识别；
- 口语评分；
- AI作文批改；
- 自动抓取或转载第三方版权内容；
- 自动生成大量低质量教学材料；
- ElasticSearch、Redis、对象存储等额外基础设施；
- 服务端音频转码和波形生成。

## 4. 领域架构

### 4.1 总体结构

```text
English
├── overview                 英语总览
├── vocabulary               单词独立数据域
├── grammar                  语法独立数据域
├── reading                  阅读独立数据域
├── listening                听力独立数据域
├── writing                  写作独立数据域
└── shared
    ├── taxonomy             统一语义标签
    ├── cefr                 CEFR难度标准
    ├── exercise             统一练习引擎
    ├── learning-bundle      读听写学习组合
    ├── learning-record      学习记录和薄弱点
    └── vocabulary-family    词族扩展
```

### 4.2 独立与共享边界

| 能力 | 是否共享 | 说明 |
| --- | --- | --- |
| 内容正文 | 否 | 阅读文章、听力材料、写作资源必须独立存储 |
| 分类方式 | 否 | 阅读、听力、写作按各自业务本质分类 |
| 标签字典 | 是 | 主题、场景、功能、能力使用统一语义词表 |
| CEFR标准 | 是 | 六级标准统一，但每个模块保存不同量化指标 |
| 练习基础结构 | 是 | 题干、题型、配置、解析和顺序统一 |
| 内容与练习关联 | 否 | 使用模块专属关联表保持外键完整性 |
| 学习组合 | 是 | 显式关联阅读、听力和写作内容 |
| 学习记录 | 是 | 统一保存状态、得分、用时、薄弱点和掌握度 |
| 发布生命周期 | 是 | 固定使用 DRAFT/PUBLISHED/WITHDRAWN |

禁止建立只有 `module_type + content_id`、却没有真实外键的内容关联表。共享能力必须通过模块专属映射表与业务表建立外键。

## 5. 统一分类与难度标准

### 5.1 语义标签维度

统一标签表支持以下维度：

- `TOPIC`：主题；
- `SCENE`：使用或听力场景；
- `FUNCTION`：表达功能；
- `ABILITY`：能力目标；
- `GENRE`：文体；
- `FORMAT`：内容或交流形式。

标签允许最多两级：一级标签表示大类，二级标签表示具体主题。禁止三级及更深层级，禁止循环父级，禁止跨维度父子关系。

首批主题标签：

- 科技：人工智能、信息技术、生物技术、工程技术；
- 社会：社会发展、人口问题、教育、城市发展；
- 经济：市场、商业、金融、全球经济；
- 环境：气候变化、生态保护、能源问题；
- 文化：历史、艺术、语言、传统文化；
- 健康：医学、心理健康、生活方式；
- 政治：国际关系、公共政策、国家治理；
- 哲学与思想：思想观点、人类认知、价值讨论。

首批功能标签至少包括：描述、说明、比较、举例、因果、转折、论证、反驳、总结。

首批能力标签至少包括：句子理解、信息提取、主题句识别、结构分析、指代判断、逻辑判断、隐含推断、语音识别、信息保持、观点组织、衔接连贯和风格控制。

### 5.2 CEFR标准

保存 A1、A2、B1、B2、C1、C2 六级标准。CEFR等级必须由管理员选择，系统根据计算指标给出建议，不得未经确认自动覆盖人工等级。

| 等级 | 词汇量参考 | 阅读平均句长 | 阅读内容建议 | 听力速度建议 | 写作目标建议 |
| --- | ---: | ---: | --- | --- | --- |
| A1 | 200–500 | 5–8词 | 单句、简单通知、短对话 | 70–90 WPM | 30–60词 |
| A2 | 500–1000 | 8–12词 | 2–3个短段落 | 90–110 WPM | 60–120词 |
| B1 | 1000–2000 | 12–18词 | 3–5段说明或叙述 | 110–140 WPM | 120–200词 |
| B2 | 2000–3500 | 15–25词 | 多段说明文和议论文 | 140–170 WPM | 200–300词 |
| C1 | 3500–5000 | 20–30词 | 长篇学术或专业文本 | 170–200 WPM | 300–500词 |
| C2 | 5000+ | 25词以上 | 复杂多主题和高密度文本 | 190+ WPM | 500词以上 |

上述范围用于发布提醒，不作为数据库硬约束。数据库只约束等级值合法、统计值非负。

## 6. 阅读系统需求

### 6.1 分类体系

阅读采用三条轴线：

1. 能力层级：基础阅读、结构阅读、深度阅读。
2. 主题标签：科技、社会、经济、环境、文化、健康、政治、哲学与思想。
3. 文体标签：说明文、议论文、新闻报道、学术文本、应用文本。

一篇文章必须有：一个能力层级、一个CEFR等级、至少一个主题标签和一个文体标签。

### 6.2 文章内容

阅读文章保存：

- 标题、稳定slug、摘要、封面；
- Markdown正文；
- 能力层级、CEFR等级；
- 主题、文体、能力和语法标签；
- 来源名称、来源URL、作者或版权说明；
- 正文词数、去重词数、平均句长、最长句长、预计阅读时间；
- 发布状态、发布时间、创建和更新时间。

正文统计在后端保存时重新计算，不能信任前端提交值。

### 6.3 阅读题型

首期支持：

- 单项选择；
- 正误判断；
- 句子与释义匹配；
- 段落匹配；
- 句子或段落排序；
- 指代关系判断；
- 因果关系判断；
- 主旨选择；
- 隐含信息推断；
- 结构图填充。

### 6.4 阅读后台

后台路由：

- `/admin/english/reading`
- `/admin/english/reading/articles/new`
- `/admin/english/reading/articles/:articleId/edit`
- `/admin/english/reading/articles/:articleId/exercises`

阅读工作台包含：

1. 顶部数据摘要：总文章、已发布、草稿、各CEFR数量、缺少练习数量。
2. 筛选：关键词、状态、能力层级、CEFR、主题、文体。
3. 卡片列表：封面、标题、摘要、标签、词数、预计时长、状态、更新时间。
4. 操作：编辑、预览、发布/撤回、练习管理、复制、删除。
5. 编辑页：粘性操作栏、正文编辑区、元信息侧栏或分组卡片、发布检查。
6. 练习页：题目列表、拖拽排序、题型编辑器、答案和解析预览。

删除已发布文章必须二次确认。存在学习记录时默认不允许物理删除，应先撤回；后期允许归档，不允许级联误删记录。

### 6.5 阅读前台

公开路由：

- `/english/reading`
- `/english/reading/:slug`

阅读中心包含能力路线、主题导航、文体筛选、CEFR筛选和文章卡片。筛选状态写入URL查询参数，刷新、分享、前进后退必须保持。

文章详情桌面端采用三栏：

- 左侧：文章元信息、能力目标、相关词汇和语法点；
- 中间：标题、摘要、正文、练习、上一篇/下一篇；
- 右侧：Markdown H2–H4页内大纲和阅读进度。

1024px隐藏右侧大纲；720px以下将辅助信息和大纲改为可展开面板。正文页面标题为唯一H1。

## 7. 听力系统需求

### 7.1 分类体系

听力采用三条轴线：

1. 场景：日常交流、学习场景、工作场景、新闻场景。
2. 形式：短对话、长对话、独白、新闻听力、演讲与讲座。
3. 专项能力：语音识别、信息捕获、逻辑理解。

材料同时使用统一主题标签，从而与阅读和写作建立关联。

### 7.2 听力材料

听力材料保存：

- 标题、slug、摘要、封面；
- 音频媒体ID；
- 场景、形式、CEFR、主题和能力标签；
- 时长、WPM、说话人数、口音、来源和版权说明；
- 补充Markdown讲解；
- 发布生命周期和时间信息。

听力列表接口不返回字幕段和讲解正文。进入详情页后才加载完整材料。

### 7.3 字幕与时间轴

字幕段字段：

- `start_ms`：开始毫秒；
- `end_ms`：结束毫秒；
- `speaker`：可空；
- `text_en`：英文原文；
- `text_zh`：可空中文释义；
- `sort_order`：稳定顺序。

约束：开始时间必须非负，结束时间必须大于开始时间，同一材料的字幕排序不得重复。服务层检查相邻字幕明显重叠并给出警告；轻微重叠允许人工确认。

### 7.4 语音规则支线

独立管理以下规则：

- 连读 `LINKING`；
- 弱读 `WEAK_FORM`；
- 同化 `ASSIMILATION`；
- 省音 `ELISION`；
- 重音 `STRESS`；
- 语调 `INTONATION`。

每条规则保存标题、slug、摘要、Markdown讲解、CEFR、排序和状态。规则示例使用结构化记录，保存短语、IPA、自然发音音频、说明和顺序。

### 7.5 听力题型

首期支持：

- 听音辨词；
- 最小对立音辨析；
- 连读或弱读填空；
- 数字、时间、地点和人名填空；
- 关键信息选择；
- 主旨选择；
- 说话者态度；
- 因果、转折和顺序判断；
- 简短听写。

### 7.6 听力后台

后台路由：

- `/admin/english/listening`
- `/admin/english/listening/materials/new`
- `/admin/english/listening/materials/:materialId/edit`
- `/admin/english/listening/materials/:materialId/transcript`
- `/admin/english/listening/materials/:materialId/exercises`
- `/admin/english/listening/pronunciation`
- `/admin/english/listening/pronunciation/new`
- `/admin/english/listening/pronunciation/:ruleId/edit`

字幕编辑器必须支持：播放/暂停、点击字幕跳转、设置当前开始/结束时间、拆分、合并、上下移动和中英文编辑。第一版不实现复杂波形拖拽。

### 7.7 听力前台

公开路由：

- `/english/listening`
- `/english/listening/:slug`
- `/english/listening/pronunciation/:slug`

播放器功能：

- 0.75、1.0、1.25、1.5倍速；
- 前后5秒；
- 当前句循环；
- 当前字幕高亮；
- 隐藏字幕、英文字幕、双语字幕；
- 键盘空格播放/暂停，左右键跳转；
- 移动端固定底部控制条；
- 页面离开时停止播放并释放事件监听。

听力练习默认先隐藏答案和完整字幕。用户提交后再显示答案、解析和可回放时间段。

## 8. 写作系统需求

### 8.1 内容结构

写作系统包含四种资源：

1. 表达训练 `EXPRESSION_LESSON`；
2. 文体训练 `GENRE_LESSON`；
3. 范文 `MODEL_ESSAY`；
4. 写作模板 `TEMPLATE`。

表达训练固定四层：

- 句子层：句子扩展、句式变化、合并与转换；
- 段落层：主题句、支撑句、结论句；
- 衔接层：因果、转折、递进、指代和过渡；
- 风格层：正式/非正式、客观/主观、学术/日常。

文体训练包含：描述类、说明类、议论类、应用类、学术表达。

### 8.2 写作资源

资源保存：

- 类型、标题、slug、摘要、Markdown正文、封面；
- CEFR、表达层级、文体、功能、主题和能力标签；
- 推荐目标字数和预计训练时间；
- 结构化模板配置；
- 发布状态和时间。

模板配置用于生成可填写区块，例如：引言、主题句、论据、反驳、结论。配置存JSON，但后端必须按固定Schema校验，禁止保存任意未知结构。

### 8.3 写作任务

任务保存：

- 题目和背景；
- 写作要求；
- 最少/最多字数；
- 建议时间；
- 评分量表；
- 自评清单；
- 关联范文和模板；
- 排序和状态。

评分量表默认包含：内容完成度、结构组织、语言准确性、词汇丰富度、衔接连贯和格式规范。

### 8.4 写作后台

后台路由：

- `/admin/english/writing`
- `/admin/english/writing/resources/new`
- `/admin/english/writing/resources/:resourceId/edit`
- `/admin/english/writing/prompts/new`
- `/admin/english/writing/prompts/:promptId/edit`

写作工作台采用四个清晰页签，不把所有内容塞进一张表：表达训练、文体训练、范文库、模板库。顶部摘要显示各类数量、发布数量和缺少练习数量。

### 8.5 写作前台

公开路由：

- `/english/writing`
- `/english/writing/lessons/:slug`
- `/english/writing/samples/:slug`
- `/english/writing/templates/:slug`
- `/english/writing/practice/:promptId`

练习页包含题目、要求、评分量表、纯文本写作区、字数统计和自动保存。游客草稿使用版本化的 `localStorage` 键，至少保存内容、更新时间和题目ID。

提交后提供：

- 字数和段落统计；

### 9.1 迁移顺序

当前最高迁移为V8。后续迁移建议固定如下，迁移一旦进入任何环境不得修改原文件：

| 迁移 | 内容 |

如果开发期间某个迁移已在本地或测试数据库执行，禁止回头修改校验和；应新增下一版本修复迁移。

### 9.2 共享表

#### `english_taxonomy_term`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| id | BIGINT | 主键自增 |
| parent_id | BIGINT NULL | 自外键，删除RESTRICT |
| dimension | VARCHAR(20) | 固定合法值 |
| name | VARCHAR(100) | 非空 |
| slug | VARCHAR(100) | 全局唯一、稳定 |
| description | VARCHAR(500) NULL | 说明 |
| sort_order | INT | 大于0 |
| enabled | BOOLEAN | 默认true |
| created_at/updated_at | DATETIME(6) | UTC |

索引：`(dimension,parent_id,sort_order,id)`。服务层限制最多两级、同维度父子、无循环。

#### `english_cefr_standard`

主键使用等级代码A1–C2，保存词汇量、阅读句长、听力WPM、写作字数和描述。所有数值允许上界为空，但非空值必须大于等于0，最小值不能大于最大值。

#### `english_exercise`

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| module_type | READING/LISTENING/WRITING |
| question_type | 固定题型代码 |
| prompt_markdown | 题干 |
| config_json | 选项、标准答案、排序或填空配置 |
| explanation_markdown | 答案解析 |
| score_value | 默认分值 |
| sort_order | 顺序 |
| publish_status | 生命周期 |

`config_json`最大建议64KB。请求层和服务层必须按题型验证JSON结构，不能只检查JSON语法。

模块内容通过下列专属表关联：

- `english_reading_article_exercise`；
- `english_listening_material_exercise`；
- `english_writing_prompt_exercise`。

每个练习只能属于一个模块内容。服务和集成测试负责拒绝重复跨模块绑定。

#### `english_learning_bundle`

保存标题、slug、摘要、主CEFR、封面、发布状态和排序。三个模块分别使用独立映射表，一个组合允许多个阅读、听力和写作项目。

### 9.3 阅读表

#### `english_reading_article`

关键字段：`title`、`slug`、`summary`、`body_markdown`、`cover_media_id`、`reading_level`、`cefr_level`、`source_name`、`source_url`、`copyright_note`、`word_count`、`unique_word_count`、`average_sentence_words`、`max_sentence_words`、`estimated_minutes`、`publish_status`、`sort_order`和时间字段。

关键约束：

- slug唯一；
- reading_level只允许1、2、3；
- CEFR外键存在；
-统计值非负；
- 生命周期时间与状态一致；
- 封面外键删除时SET NULL。

索引：

- `(publish_status,cefr_level,updated_at,id)`；
- `(reading_level,publish_status,sort_order,id)`；
- slug唯一索引。

#### `english_reading_article_tag`

联合主键 `(article_id,term_id)`，删除文章时CASCADE，删除已使用标签时RESTRICT。额外保存 `tag_role`，允许标记主主题或普通标签。

### 9.4 听力表

#### `english_listening_material`

关键字段：标题、slug、摘要、讲解Markdown、音频ID、封面ID、CEFR、duration_seconds、words_per_minute、speaker_count、accent、source、copyright、状态和时间。

音频ID必须指向 `asset_type='AUDIO'`，该跨表类型约束由服务层验证；数据库保证媒体行存在。

#### `english_listening_segment`

联合唯一索引 `(material_id,sort_order)`，查询索引 `(material_id,start_ms)`。删除材料时字幕可以CASCADE；删除音频媒体时RESTRICT，防止已发布听力突然失效。

#### `english_listening_pronunciation_rule`

保存规则类型、标题、slug、摘要、正文、CEFR、顺序和状态。规则类型限制为六个固定值。

#### `english_listening_rule_example`

保存规则ID、短语、IPA、说明、音频ID和排序。示例音频同样必须验证为AUDIO。

### 9.5 写作表

#### `english_writing_resource`

关键字段：resource_kind、标题、slug、摘要、正文、封面、CEFR、expression_level、target_words_min/max、estimated_minutes、template_schema_json、状态和时间。

约束：最小字数不能大于最大字数；只有TEMPLATE允许非空模板Schema；表达层级固定为SENTENCE/PARAGRAPH/COHESION/STYLE或空。

#### `english_writing_prompt`

保存标题、slug、背景、要求、最少/最多字数、建议时间、rubric_json、checklist_json、关联模板、关联范文、状态和时间。

模板和范文关联必须指向正确resource_kind，由服务层校验。

### 9.6 词族扩展

#### `vocabulary_word_family`

保存规范化主词、slug和说明。主词不改变现有 `vocabulary_word` 的主词条计数。

#### `vocabulary_family_member`

保存family_id、spelling、part_of_speech、phonetic_us、translation、cefr_level、example_sentence、example_translation和排序。

#### `vocabulary_word_family_link`

关联现有词条与词族。迁移不得自动解析复杂 `inflections` 文本；后台允许逐步补录和匹配。

### 9.7 学习记录

第一版建立单站点学习档案，不开放注册。建议表：

- `english_learner_profile`：单例档案，默认只供管理员同步；
- `english_learning_record`：状态、得分、用时、尝试、薄弱点、掌握度、下次复习；
- `english_exercise_attempt`：每次答题快照和得分；
- `english_writing_submission`：写作草稿、提交版本、自评结果和统计。

学习记录通过阅读、听力、写作专属映射表关联内容，保持外键完整性。`weak_points`使用受控能力标签ID数组，不保存任意不可统计字符串。

## 11. 后端实现规范

### 11.1 包结构

```text
com.starrainnotes.english
├── shared
│   ├── taxonomy
│   ├── cefr
│   ├── exercise
│   ├── bundle
│   └── learning
├── reading
│   ├── controller
│   ├── dto
│   ├── entity
│   ├── mapper
│   ├── repository
│   └── service
├── listening
└── writing
```

简单单表CRUD使用MyBatis-Plus；复杂筛选、统计、投影和批量查询使用JdbcTemplate专属Repository。禁止在Controller直接拼SQL或编写业务事务。

### 11.2 服务规则

- 所有写操作由Service控制事务。
- 创建、更新、发布、撤回和删除分别建方法，不用一个万能save方法隐式改变状态。
- 标签关联更新采用“校验全部目标—删除旧关联—插入新关联”的同一事务。
- 排序使用 `targetIndex`，后端统一归一化为10、20、30。
- 排序归一化采用两阶段临时值，避免唯一索引冲突。
- 公开查询必须同时检查内容状态和所有必要父资源状态。
- 删除前查询关联记录并返回明确错误，不依赖数据库异常向用户展示。
- 请求DTO使用Bean Validation；字符串统一trim，空字符串转换为null的规则保持一致。
- 任何客户端提交的统计值、媒体类型、所有权和答案分数都必须由后端重新校验。

### 11.3 发布检查

发布阅读文章前至少检查：正文、主题、文体、CEFR和合法slug。

发布听力材料前至少检查：合法AUDIO媒体、时长、场景、形式、CEFR和至少一个字幕段或明确“无字幕”标记。

发布写作资源前至少检查：正文、资源类型、CEFR；模板还要检查Schema，任务还要检查字数范围和评分量表。

发布失败返回字段级问题列表，前端在发布检查抽屉中展示，不只显示通用“操作失败”。

## 13. 音频媒体与部署

### 13.1 媒体升级

修改媒体类型约束，新增 `AUDIO`。允许：

- MP3：`audio/mpeg`；
- M4A：`audio/mp4`或经过规范化的兼容MIME；
- OGG：`audio/ogg`。

默认音频最大50MB，通过 `AUDIO_MAX_BYTES` 配置。后端校验扩展名、声明MIME和文件签名：MP3检查ID3或MPEG同步头，M4A检查ISO BMFF `ftyp`，OGG检查 `OggS`。

媒体选择器增加音频筛选、文件名、大小、类型和内嵌试听。图片Markdown上传流程保持不变。

### 13.2 Nginx要求

生产环境：

- `/uploads/`直接由Nginx映射媒体目录；
- 保留 `Accept-Ranges: bytes`；
- 设置正确音频MIME；
- 媒体文件缓存30天；
- `client_max_body_size`略高于后端音频上限，例如55m；
- 不对音频启用无意义的动态压缩；
- HTML和API仍按现有策略代理。

验收必须验证音频请求返回206范围响应，而不是每次从头下载整个文件。

## 14. 搜索与性能

### 14.1 搜索类型

### 14.2 搜索投影

V13建议新增 `site_search_document` 作为只读搜索投影，字段至少包含：type、source_id、title、summary、search_text、public_path、activity_at和published。

业务内容发布或更新时在同一事务更新投影；撤回或删除时移除/禁用投影。迁移需回填已有教程、章节、博客、作品和语法内容。

搜索接口在数据库完成类型筛选、数量统计、排序和分页，不再把所有命中正文加载到JVM后分页。若暂不启用MySQL ngram全文索引，至少限制候选数量并优先匹配标题和摘要。

### 14.3 2核2GB服务器要求

- 列表DTO不携带正文和字幕；
- 页面和接口均分页；
- 单次查询禁止N+1；
- 标签数量使用聚合查询一次返回；
- 公开字典和英语首页摘要允许短时缓存；
- 音频不经过JVM传输；
- 避免引入Redis、Elasticsearch和大型音频处理依赖；
- 生产构建保持路由级代码拆分；
- 图片继续使用WebP优先和懒加载。

## 15. 安全、版权与数据保护

- 管理接口必须为管理员权限，未来即使加入普通用户，也必须将 `/api/v1/admin/**` 从“已认证”升级为明确 `ROLE_ADMIN`。
- 游客不得匿名向服务器写学习记录或作文，避免垃圾数据和磁盘滥用。
- 所有URL、Markdown和文本继续通过现有安全渲染链路。
- 外部来源必须保存来源名称、URL和版权说明；不得自动采集不明版权文章和音频。
- 上传音频不得信任文件扩展名和浏览器MIME。
- 删除媒体前检查业务引用；听力正在引用的音频不得直接删除。
- 写作草稿本地存储不得保存密码、Cookie或其他敏感信息。
- 日志不得记录作文全文、答案配置、Session ID和CSRF Token。

## 19. 开发与代码审查规范

1. 不读取并盲从项目中旧的需求文档；以真实代码、本文档和项目所有者最新指令为准。
2. 修改前先检查工作树，禁止覆盖用户现有未提交改动。
3. 文件修改使用最小范围，禁止顺手重构无关模块。
4. 不使用 `git reset --hard`、强制推送或批量删除。
5. Flyway迁移不可回改；所有修复使用新迁移。
6. SQL必须参数绑定，禁止拼接用户输入。
7. 所有公开接口需要明确的草稿/撤回测试。
8. DTO与数据库实体分离；前端不得依赖数据库字段命名。
9. 复杂规则必须有后端测试，不能只依赖前端禁用按钮。
10. 每完成一个子阶段立即运行相关测试，不要等全部代码完成后集中排错。
11. 所有新页面必须同时考虑桌面、平板、移动端和亮暗主题。
12. 新依赖必须说明必要性、体积和替代方案；默认不引入大型依赖。

## 20. Git版本控制规范

### 20.1 分支规则

- 所有开发分支使用 `codex/` 前缀。
- 分支必须从最新 `origin/clean` 创建。
- 开发分支只包含本阶段文件。
- 用户未跟踪文件不得纳入提交。
- 每阶段推送远端但不自动合并clean，等待验收。

### 20.2 合并规则

验收后：

1. `git fetch origin clean`；
2. 检查远端clean是否出现新提交；
3. clean未变化时使用 `git merge --ff-only`；
4. 出现分叉时停止，不使用rebase覆盖或强推；
5. 合并后推送clean；
6. 再从更新后的clean创建下一阶段分支。

### 20.3 提交质量

每次提交应满足：

- 单一清晰目标；
- 不混入构建产物、IDE配置、上传文件、环境变量和原始素材；
- `git diff --check`通过；
- 后端相关测试通过；
- 前端类型检查和构建通过；
- 提交消息使用清晰中文或项目统一格式。

## 21. DeepSeek Harness执行指引

每次只执行本文一个阶段。开始阶段前，开发智能体必须先输出：

1. 当前分支、HEAD和origin/clean；
2. 工作树中已有修改与未跟踪文件；

4. 本阶段迁移版本；

执行过程中必须遵守：

- 先后端约束和测试，再前端页面；
- 先列表和详情接口，再管理交互；
- 先真实数据流，再视觉装饰；

- 不用静态假数据掩盖接口失败；
