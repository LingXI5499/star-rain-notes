# 星雨笔录 Markdown 渲染规范（已对照仓库）

## 真实兼容的核心语法

仓库：https://github.com/LingXI5499/star-rain-notes

关键实现（2026-10-12 对照本仓库源码；后续以当前实现为准）：

- `frontend/src/shared/markdown/markdownCodeGroup.js`：解析 `::: code-group` 自定义容器与标签。
- `frontend/src/shared/markdown/markdown.js`：注册 markdown-it-container，前台把代码组增强成可切换页签。
- `frontend/src/shared/editor/MarkdownEditor.vue`：Vditor IR 编辑器与创建代码组的工具栏。

**标准结构（五语言，同一个方法内展示）：**

````markdown
::: code-group C|C++|Java|Python|JavaScript

```c
/* 此处是完整的 C 实现 */
```

```cpp
// 此处是完整的 C++ 实现
```

```java
// 此处是完整的 Java 实现
```

```python
# 此处是完整的 Python 实现
```

```javascript
// 此处是完整的 JavaScript 实现
```

:::
````

格式要点：

1. `::: code-group C|C++|Java|Python|JavaScript` 必须独占一行，标签用英文竖线 `|` 分隔；支持更多标签；默认五语言顺序固定，用户指定组合时保持标签、围栏与检查器参数同序。
2. 围栏首行使用 `c`, `cpp`, `java`, `python`, `javascript`，这五种语言已在本站 highlight.js 注册；采用其他语言时先核对实际渲染支持，不臆造高亮能力。
3. 默认组内放**五个普通 Markdown 围栏块**，指定组合时每种语言一个；块与块之间空一行；末尾闭合 `:::` 独占一行。
4. 不得把整个 `::: code-group` 外面再包一层 ` ```markdown `（那只会显示源码）；不得用 `\n` 的字面字符代替真实换行。
5. 正文其他文字不得挤在容器起始标记或结尾标记同一行。
6. 如一个代码示例本身需要三反引号，使用比内部最长连续反引号更长的外层围栏，避免提前闭合。
7. 多语言代码组按**解法**划分，每方法一个，不要按语言划分“所有 C 解法”“所有 Java 解法”。
8. 自定义语言标签是 Markdown 容器的扩展，不是所有第三方 Markdown 编辑器的标准语法。用户此前确认过，在当前星雨笔录中复制发布可正常显示，**不能未经核实就把复制预览的差异判作网站故障**。

## 标题、公式、表格、图片

- 站点列表/编辑表单提供文章标题，因此**正文不写 `# 标题`**；正文使用 `## 一、题目描述`。
- 数学公式行内 `$...$` / 块级 `$$...$$`；确保公式运算关系正确。
- 表格保持标准 Markdown，最好列数 4–7、行内容不宜过长，兼顾手机阅读。
- 题主已有真实图片，如 `![双指针流程图](/api/media/assets/<已有ID>/content)`，可在正文保留；**只能复用用户真实提供的路径**，绝不编造媒体 ID。
- 源码注释使用各语言正确语法；不要在围栏代码中插入 HTML 实体 `&#x20;` 替代空格。
- 文中反斜杠转义应保持合规；不应产生 `\##`、`\*` 等把 Markdown 标题或列表显示成普通文字的失误。

## 编辑与发布注意

1. 建议保存纯 UTF-8 `.md` 文件，检查源文件的换行和围栏，再复制完整正文。
2. 使用站点的预览/发布页面观察是否变成可切换代码页签。部分富文本工具可能对自定义容器做格式化，不要先将源文件转成富文本再复制。
3. 摘要、标题和标签属于发布表单字段，默认独立提供，不混入文章 Markdown。
4. 如果代码组展示成普通文字：先核查**保存后的 Markdown 原文**是否仍保留换行、`:::` 与围栏，再区分编辑器与前台渲染器问题；截图本身不足以判断后端根因。
5. 对站点的支持特性，若将来 GitHub main 发生变化，应重查上述真实实现，不假设永远不变。
