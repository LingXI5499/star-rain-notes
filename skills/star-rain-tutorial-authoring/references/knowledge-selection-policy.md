# 知识点准入与来源规则

## 为什么要教

候选知识至少具有一项明确价值，核心主线优先保留同时满足多项的内容：

- 是后续学习或完成目标任务的直接前置；
- 在读者的实际学习、操作、工作或应用场景中经常出现；
- 直接影响正确性、理解、决策或错误成本；
- 能补齐用户既有教材、案例或练习中的关键缺口。

先确定读者和目标，再判断价值。只有求职或考试教程才需要招聘、考纲、试题等需求信号；软件安装的目标可能只是能够独立安装与验证，非编程知识的目标可能是解释现象或完成计算。不要为了新特性、工具数量或百科式覆盖打断认知顺序。

## 凭什么这样讲

| 主题 | 首选事实依据 | 适合的验证 |
| --- | --- | --- |
| 编程语言、框架、数据库、API | 适用版本的官方规范、文档、接口契约与源码 | 最小程序、请求、查询或可复现测试 |
| 软件安装、命令、工具操作 | 官方安装说明、系统要求、对应版本界面与帮助 | 在注明的环境中执行步骤并检查结果 |
| 数学、原理与非编程学科 | 权威教材、标准、原始研究或可追溯的学科资料 | 核对推导、单位、假设、反例或案例 |
| 实践流程、对比与选型 | 产品官方资料、真实需求与可说明条件的案例 | 条件匹配、样例演练与验收检查 |

用户旧教程可用于覆盖检查和案例线索；社区文章可用于发现疑点，关键事实应上溯查证。使用频率证据只能说明学习需求，不能代替事实证据。教程风格参考不能成为事实来源。

涉及版本、环境或其他可能变化的信息时查证对应资料，不把 Java 的 JLS、JDK 或某个版本作为其他领域的通用依据。资料与实测不一致时先解释环境和适用条件，再决定如何表述。

## 主线取舍

- **CORE**：必要前置、常用能力或关键边界，在本章讲清。
- **COMMON**：有用但由其他章节负责，保留指向，避免提前展开。
- **OPTIONAL**：仅对部分读者或条件有价值，按需补充。
- **OMIT**：无明确学习收益、重复或会打断当前目标，移出本章。

同一知识在不同课程中的优先级可以不同。JavaSE 特定课程的 `var`、JShell 取舍见领域上下文，不设全局黑名单。
