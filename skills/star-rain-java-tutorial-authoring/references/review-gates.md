# 章节审核门禁

## 结构

- 元数据只有 `title`、`summary`，分别渲染为页面 H1 和标题下摘要；正文不重复二者。
- 正文必须且只能依次出现学习目标、核心知识、问题、练习题四个 H2。
- H3 只表示真实知识点、问题类别或练习类型，并与父级编号一致。
- 普通知识章的核心知识点从 `2.1` 开始连续编号；每篇章节重新计数。
- 没有把定义、作用、语法、代码示例、注意事项等写作标签做成标题。
- H4 仅用于确有必要的子知识点，不能用来继续拆模板。

## 相关性

- 每个核心知识点都有明确的学习依赖、秋招价值或工作价值。
- 便利工具和低频新特性没有因为“JDK 21 支持”就进入核心。
- `var`、JShell 等内容只有在需求得到证明时才出现。

## 内容

- 开头直接说明是什么、怎么用、用在哪里，不做历史铺垫和重复总结。
- 语法/API 示例完整、最小、可运行，注释说明意图或易错行为。
- 安装、工具和原理内容没有为了套模板强加代码。
- 多项对比使用表格，明确流程使用步骤，原理按因果或执行顺序解释。
- 注意事项可以没有；保留的每一条都对应真实故障、关键边界或高频秋招混淆，且表达简短。
- 没有“常见错误大全”“最终认知模型”“一句话解释”等重复或自我描述式栏目。

## 证据与验证

- “为什么教”有需求信号；“如何讲”有官方技术来源。
- 公开可运行代码已在 JDK 21 验证；错误代码明确标注用途。
- 问题与练习映射本章知识点，不要求尚未学习的内容。

任一项失败则状态为 `REVISE`。全部通过后，AI 最多标记 `READY_FOR_HUMAN_REVIEW`。
