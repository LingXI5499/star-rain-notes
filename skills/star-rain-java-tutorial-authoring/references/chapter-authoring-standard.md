# 章节写作与结构标准

## 1. 标题只负责导航

星雨笔录先把元数据中的 `title` 和 `summary` 渲染为页面 H1 与标题下摘要，再渲染 Markdown 正文。正文 H2～H4 会自动进入右侧“本页导航”，因此正文不重复 H1 和摘要，标题只标记文章结构与真实知识点。

| Markdown | 普通知识章示例 | 用途 |
|---|---|---|
| 元数据 `title` | 字面量、变量与作用域 | 页面 H1，不在正文重复 |
| 元数据 `summary` | 学习变量的基本使用与有效范围 | H1 下方摘要，不在正文重复 |
| H2 | `一、学习目标` | 页面一级结构 |
| H2 | `二、核心知识` | 页面一级结构 |
| H3 | `2.1 字面量` | 可独立学习和检索的知识点 |
| H4 | `2.1.1 整数字面量` | 仅在确有独立子知识时使用 |

每篇章节都重新开始编号。这里的 `2.1` 表示正文第二部分的第一个知识点，不继承课程分组号或网站章号。

以下内容通常不是标题：定义、作用、语法、应用场景、示例、运行结果、注意事项。它们应使用短段落、行内代码、代码块、表格、列表或引用块表达。

## 2. 固定文章骨架

```text
## 一、学习目标
## 二、核心知识
### 2.1 知识点一
### 2.2 知识点二
## 三、问题
## 四、练习题
### 4.1 代码阅读（按需）
### 4.2 代码编写（按需）
```

右侧“本页导航”会自动列出核心知识点，因此不再额外写一份重复的“知识点目录”。“学习目标”用 2～4 条描述学完能做什么，不罗列教学过程。

这四个 H2 适用于所有公开文章，不能增删、改名或调换顺序。安装教程的准备工作与安装步骤、原理文章的关系与流程、API 文章的用法与示例，都放在 `二、核心知识` 下继续组织。

### 标题与摘要

- `title` 使用简短名词短语，直接说明文章主题，不写“完全指南”“保姆级教程”等修饰语。
- `summary` 用 1～2 句说明范围和学完能解决的问题，不重复标题，不写教学过程。
- H1 和摘要属于网站页面头部，不属于 Markdown 正文标题数量。

## 3. 语法与 API 的正文顺序

一个知识点通常按以下顺序自然展开，但这些不是固定标题：

1. 用一小段说明它是什么、基本写法和常见使用场景；能一句说清就只写一句。
2. 有多项类型、规则或选择时使用紧凑表格。
3. 紧跟一个综合示例；不同场景差异明显时再拆成多个短示例。
4. 只在确有价值时补 0～3 条提醒，可写成 `> 注意：...` 或短列表。

示例必须围绕当前知识点，注释解释意图、边界或容易误解的行为，不把每一行代码翻译成中文。

## 4. 不同内容采用不同写法

| 内容类型 | 推荐结构 | 不应强制出现 |
|---|---|---|
| 语法 / API | 短解释、必要表格、带注释示例、真实提醒 | 四个固定小标题 |
| 安装 / 环境 / IDE | 核心知识内写前提、编号步骤、验证、必要排错 | Java 示例代码 |
| 原理 / 体系介绍 | 核心知识内写结论、关系或流程、边界 | 为了凑结构而写的代码 |
| 对比 / 选型 | 选择结论、对比表、典型场景、易错边界 | 重复解释每个表格单元 |
| 综合练习 | 场景、要求、起始材料、验收标准 | 定义和语法栏目 |

“该是什么就写什么”：步骤明确就写步骤，关系复杂就用表格或图，原理内容就按因果顺序解释。

## 5. 篇幅与训练

- 每章通常 2～6 个核心知识点。
- 正文默认 2,000～6,000 字符；超过 8,000 必须复核；超过 12,000 视为结构失败。
- 一个知识只完整解释一次，不追加“常见错误大全”“最终认知模型”等重复内容。
- 问题通常 5～10 个，覆盖理解、判断和关键边界。
- 练习根据章节特点选择代码阅读、代码编写、操作验证或原理判断，并提供明确验收条件。
- 下一章负责的内容最多做一句必要指向，不提前展开。
