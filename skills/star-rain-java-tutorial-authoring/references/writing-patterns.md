# 四块正文的写法选择

所有公开文章都使用同一个页面骨架：H1 标题、摘要，以及学习目标、核心知识、问题、练习题四块正文。下面只说明四块内部如何适应不同内容，不是额外模板。

## 1. 通用骨架

````markdown
---
title: "章节标题"
summary: "文章范围，以及学完能够解决的问题。"
---

## 一、学习目标

- 能够完成的具体任务。
- 能够判断的关键边界。

## 二、核心知识

### 2.1 知识点一

根据内容使用短段落、表格、代码或步骤。

### 2.2 知识点二

继续按认知顺序展开。

## 三、问题

1. 用于检查理解的问题。

## 四、练习题

### 4.1 适合本章的练习类型

给出任务与验收标准。
````

网站使用 `title` 和 `summary` 渲染页面 H1 与摘要；Markdown 正文不再写 H1。正文只能有示例中的四个 H2。

## 2. 语法或 API

在每个核心知识点开头，用一小段同时说明是什么、基本写法和使用场景；随后紧跟必要表格或带注释代码。不同场景差异明显时可以给多个短示例，没有真实易错点时不写注意事项。

练习优先使用代码阅读和代码编写：

```markdown
## 四、练习题

### 4.1 代码阅读
### 4.2 代码编写
```

## 3. 安装、环境或 IDE 操作

仍然只使用四个 H2，把前提、步骤、验证和排错放进核心知识：

```markdown
## 二、核心知识

### 2.1 准备工作
### 2.2 下载与安装
### 2.3 环境配置
### 2.4 验证结果
```

每个知识点使用有序步骤，给出点击位置、命令和预期结果。只有真实常见的失败才写排错，不为安装教程补 Java 示例代码。

练习可以是操作验证，例如独立完成安装并提交 `java -version`、`javac -version` 的正确结果。

## 4. 原理或体系说明

核心知识先给结论，再按关系或执行顺序拆分：

```markdown
## 二、核心知识

### 2.1 核心关系
### 2.2 工作过程
### 2.3 关键边界
```

适合使用关系表、流程列表或必要示意图。只有代码能够证明某个行为时才提供代码，练习可使用原理判断、流程排序或现象解释。

## 5. 对比或选型

先用一句话给出常规选择，再用表格展示差异；表后只解释不能从表格直接看出的原因和边界，不逐项复述表格。

问题用于检查“为什么这样选”，练习使用具体场景让读者做选择并说明理由。
