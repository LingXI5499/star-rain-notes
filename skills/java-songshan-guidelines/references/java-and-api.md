# Java 编码与接口速查

以下分级沿用《Java开发手册（嵩山版）》1.7.0 原文。只应用与任务相关的条目；页码为印刷页码。

## 命名、常量与格式（第 1–7 页）

- **强制**：类名用 UpperCamelCase，方法、参数和变量用 lowerCamelCase，常量用大写下划线；包名小写且按自然语义分词。命名不以 `_` 或 `$` 开始或结束，避免中文、拼音混英文及难懂的缩写；代码与注释避免歧视性用语。DO、DTO、VO 等缩写按手册例外处理。（第 1–3 页）
- **强制**：POJO 的布尔属性不要加 `is` 前缀；数据库 `is_xxx` 字段映射到无前缀的 Java 属性。接口与实现类、异常类和测试类命名要表达角色。（第 2–3 页）
- **强制**：有业务含义的固定值提取为具名常量；`long` 字面量使用大写 `L`。**推荐**：按功能与作用域维护常量，不建立包罗万象的常量类；有限状态且有附加属性时考虑枚举。（第 4–5 页）
- **强制**：非空块使用一致的大括号和换行；控制关键字后留空格，运算符两侧留空格；手册使用 4 个空格缩进；行注释 `//` 后留一个空格。（第 5–6 页）

## Java 语义与数据（第 7–16 页）

- **强制**：覆写方法标 `@Override`；静态成员通过类名访问；公共接口的签名变更需兼顾调用方；使用弃用 API 前确认替代方式。（第 7 页）
- **强制**：比较包装整数的值时使用值比较，不依赖 `==` 的缓存行为；可能为 null 的对象使用安全的相等比较。重写 `equals` 时同步处理 `hashCode`，Map 键和 Set 元素尤其要注意。（第 7–8、12 页）
- **强制**：货币金额按最小单位的整数存储；浮点数不能直接用 `==` 做业务等值判断；从十进制数据创建 `BigDecimal` 时避免 `new BigDecimal(double)`，比较数值相等时注意 `compareTo` 与 `equals` 的区别。（第 8–9 页）
- **强制**：日期格式中区分 `yyyy`（日历年）与 `YYYY`（周年）；**推荐**：优先使用 `java.time` 的相应类型处理日期时间，并明确时区语义。（第 11–12 页）
- **强制**：`Collectors.toMap` 要明确重复键处理策略，并处理空值风险；`subList` 是视图，不能强转为 `ArrayList`，父列表结构变更也会影响它；集合转数组使用有类型的 `toArray(T[])`，手册示例传入长度为 0 的同类型数组。不可变集合不要增删，按具体 Map 实现核对 null 键值支持。（第 13–16 页）
- **推荐**：集合容量可以预测时预设合理值；遍历键值对时使用 `entrySet` 或当前 JDK 合适的 API。不要照抄手册中与特定 JDK 实现绑定的微性能结论。（第 15–16 页）

## 并发、控制流、注释（第 17–25 页）

- **强制**：单例及其方法要符合线程安全要求；线程和线程池应有便于排障的名称，线程池参数、队列和拒绝策略应按负载设计。使用 `ThreadLocal` 后清理。获得锁成功后才进入 `try`，在 `finally` 释放；`tryLock` 先判断是否持锁。并发更新同一记录时要防止丢失更新。（第 17–20 页）
- **强制**：`if/else/for/while/do` 使用大括号；`switch` 分支明确终止或标注贯穿，处理外部传入的 null；三目运算注意自动拆箱空指针风险。公开批量接口要限制输入规模。（第 20–23 页）
- **强制**：类和方法的文档注释使用 Javadoc；抽象方法及接口方法写清用途、参数、返回值与异常。**参考**：注释解释业务原因和不明显的约束，逻辑改变时同步维护注释。（第 24–25 页）

## 前后端 API（第 25–27 页）

- **强制**：定义 API 时明确协议、路径、方法、请求内容、状态码和响应体；生产环境使用 HTTPS，请求 URL 不携带敏感参数。列表无结果时返回空列表或集合语义，不返回 null。服务端错误向客户端提供可区分的状态、错误码、排障信息和友好的用户提示，并避免泄露敏感数据。
- **强制**：前后端 JSON 的 key 使用小写字母开头的 lowerCamelCase；可能超过 JavaScript 安全整数范围的标识符按字符串传输，避免精度丢失。对请求体、分页、批量数量等设定可执行的上限。先遵守项目既有的 API 契约；改变外部接口属于单独的兼容性决策。（第 26–27 页）
