# MySQL、工程结构与设计速查

分级与印刷页码来自《Java开发手册（嵩山版）》1.7.0。数据库版本和线上负载会影响索引、字符集及 SQL 的具体选择。

## MySQL 表、索引、SQL 和 ORM（第 38–43 页）

- **强制**：表达是否的库字段采用清楚的 `is_xxx` 语义并与 Java 布尔属性明确映射；字段类型、非空、默认值与字符集应符合业务含义。涉及金额和小数时使用精确的数据类型，不使用浮点数承载精确值。（第 38–39 页）
- **强制**：业务唯一性在数据库建立唯一约束或唯一索引；关联字段类型保持一致并评估索引。索引顺序、前缀和排序条件以实际查询与 `EXPLAIN` 为依据。手册对 join 表数、模糊搜索和索引长度给出严格限制；遇到真实例外时评估执行计划与业务负载。（第 39–40 页）
- **强制**：区分 `COUNT(*)`、`COUNT(column)` 与聚合函数对 null 的处理；`SUM` 可能返回 null。查询明确列名，避免 `SELECT *`；写 SQL 时明确条件和列所属表。（第 41–43 页）
- **强制**：MyBatis 参数使用绑定形式，不把外部输入直接拼进 SQL；动态表名、列名、排序方向使用允许列表。映射定义与实际列保持一致，避免 ORM 层意外覆盖或查询多余数据。（第 42–43 页）
- **推荐**：有分页或批量场景时对规模设置上限；对慢查询和新增索引验证实际数据分布。已有数据库迁移、命名及兼容流程优先。（第 39–43 页）

## 工程结构（第 44–47 页）

- **推荐**：按现有项目的分层边界组织代码。手册所述 Web 层负责接入与基础校验，Service 层负责业务逻辑，Manager 层放通用业务与外部服务适配，DAO 层负责数据访问。这是参考分工，不要求为小修改新增空层。（第 44–45 页）
- **强制**：依赖库升级需核对传递依赖与冲突；生产构建使用可复现的正式版本，避免无意依赖 SNAPSHOT。版本号与发布方式遵守项目现有管理规则。（第 45–46 页）

## 设计（第 48–50 页）

- **强制（手册分级）**：新存储方案和核心数据结构应经过评审并留下设计依据。复杂状态转换、跨对象调用与复杂类关系应使用适合的图或等价清晰文档表达；手册还给出用例图、状态图、时序图、类图的触发条件，具体交付量按当前设计任务范围确定。（第 48–49 页）
- **推荐**：优先考虑组合、明确抽象边界与扩展点，抽取真正重复的业务逻辑；文档描述关键约束、依赖和非功能需求。避免仅为符合模式名称而引入无收益的抽象。（第 49–50 页）
