# 星雨笔录 V2 · 作品系统完整开发文档 V1.1（当前项目对接版）

> 项目：Star Rain Notes / 星雨笔录
> 仓库：`LingXI5499/star-rain-notes`
> 对接基线：`main`，commit `50d69b99994a5c37fe22f87fc6a9ba84d939ce17`（`release: prepare v1.7.0`）
> 原始设计：`星雨笔录_V2_作品系统完整开发文档_V1.0.md`
> 本文目标：在不推翻当前 Portfolio 模块的前提下，将其升级为可长期承载软件、AI/Agent、工具、实验、内容创作等类型的通用 Works 系统。
> 当前存储策略：**继续使用 ECS 本地文件系统，不接入 OSS。**
> 数据库迁移：继续由 Flyway 管理；当前仓库最新迁移为 `V35__replace_vocabulary_with_cet4.sql`，因此本文示例从 V36 开始。若开发时仓库已出现更高版本，必须顺延编号，禁止修改已执行迁移。

---

# 0. 最终结论

本次升级不采用“删除 Portfolio、重新创建 Work 模块”的方式。

采用：

> **现有 Portfolio 兼容边界 + 通用 Works 产品模型 + Block 内容系统 + Template 模板系统 + 统一 Media 本地文件存储。**

核心决策：

1. **保留 `portfolio` 包、数据库主表、API 前缀和公开 URL。**
2. 产品层和 UI 层将 Portfolio 扩展为更广义的“作品 / Works”。
3. 不新建一套独立 `work` 主表，不把现有数据搬到另一套完全独立的业务域。
4. 继续保留 `portfolio_project` 作为作品聚合根。
5. 继续复用现有 `media_asset`、`MediaService`、`MediaPicker` 和本地 `/uploads` 文件体系。
6. 新增：
   - 作品分类 Category
   - 作品形态 Format
   - 标签 Tag
   - 动态 Section / Block
   - Template
   - Link
   - Section Media 关联
7. 当前 `body_markdown` 不立即删除，作为旧数据兼容字段；Block 系统上线后逐步退役。
8. 当前 `repository_url` / `demo_url` 不立即删除，兼容现有前端和 SEO；新增 Link 表后逐步统一。
9. 当前 `/portfolio` 不改成 `/works`，避免破坏：
   - Router
   - Search
   - Sitemap
   - SEO canonical
   - Home
   - About
   - 已被搜索引擎收录的 URL
10. 当前发布状态继续使用：
    - `DRAFT`
    - `PUBLISHED`
    - `WITHDRAWN`
11. 不引入 `HIDDEN`，不引入回收站，不引入逻辑删除。
12. 项目生命周期状态升级，但 `ONLINE` 先兼容保留，后续人工迁移后删除。
13. 当前本地媒体上传真实支持：
    - JPG / JPEG
    - PNG
    - WebP
    - PDF
    - MP3
    - M4A
    - OGG
    - ZIP
14. 当前不支持 MP4/WebM，因此 **V1.1 不实现“本地视频上传”**。
15. OSS 只作为未来基础设施替换点，不进入本阶段代码。

# 12. 为什么保留 content + data_json

不同 Block 数据形状完全不同。

因此：

```text
content
```

处理适合文本的内容：

```text
MARKDOWN
CODE
QUOTE
TEXT 类内容
```

而：

```text
data_json
```

处理结构：

```text
Timeline
Stats
Gallery Layout
Feature List
Code Metadata
Audio Config
```

例如 CODE：

```json
{
  "language": "java",
  "fileName": "UserService.java",
  "showLineNumbers": true
}
```

代码本身：

```text
content
```

```text
    → Sections 是正式内容源

sections 为空
    → fallback body_markdown
```

旧作品迁移时：

```text
body_markdown
↓
生成一个 MARKDOWN Section
```

但字段仍保留。

新作品通过 Block 创建时：

```text
body_markdown = ''
```

只用于满足旧 schema 和旧代码兼容。

当：

```text
旧数据全部迁移
旧前端 fallback 删除
Search 已切 Sections
SEO 已切 Sections
```

之后才允许新增 migration：

```text
body_markdown nullable
```

最终再考虑删除。
