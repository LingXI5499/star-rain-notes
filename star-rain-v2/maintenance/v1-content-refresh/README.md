## 执行与恢复约束

- `refresh.py` 默认只生成计划。只允许本机主库、现有预览库和本次命名的恢复验证库；读取本地私密配置，不在代码里写密码。
- `--apply` 必须提供已完整恢复且逐表校验通过的备份报告，并核对备份 SHA-256。所有业务更新使用一个事务，末尾的 CHECK 断言失败时整笔回滚。源库名称固定，执行前需要从用户原始导出恢复隔离源库。
- `prepare_media.py` 只从该导出中明确的 V1 演示域名读取公开图片，只向项目媒体目录写文件，不覆盖内容不同的现存文件。
- `verify.py` 独立检查正文摘要、关联关系、主题覆盖、双语锚点、图片文件，以及 7 张学习/系统关键表的备份前后校验值。
- 私密 SQL 计划、原始导出、备份、媒体清单及逐表报告仅写入忽略的 `.local/v1-content-refresh-20261009/`。这些文件可能含账号哈希，不提交到 Git。
- 回退时先停止对应后端，核对该库备份文件及摘要，再恢复对应完整 SQL；现有文件没有删除，媒体任务保持关闭。主库与预览库分别备份，不能互换恢复文件。

运行示例（首先准备隔离源库、图片与已验证的完整备份报告）：

```powershell
python -X utf8 maintenance/v1-content-refresh/prepare_media.py
python -X utf8 maintenance/v1-content-refresh/refresh.py --target star_rain_v2 --output E:/star-rain/star-rain-v2/.local/v1-content-refresh-20261009/plan
# 检查私密计划后，传入本次该库备份报告执行；没有 --apply 时不会改动业务数据。
python -X utf8 maintenance/v1-content-refresh/refresh.py --target star_rain_v2 --output E:/star-rain/star-rain-v2/.local/v1-content-refresh-20261009/applied --apply --backup-report <该库备份报告路径>
```

本次执行结果及服务验证见 `RESULT.md`。图片、数据库备份及用户原始 SQL 包不提交到远程仓库。
