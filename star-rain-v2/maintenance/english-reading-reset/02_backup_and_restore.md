# 阅读清空与旧写作下线：执行手册

本目录不是自动迁移。V2_037 只移除阅读等级列及旧写作两表；七张阅读表的内容清空必须独立执行。两种破坏性操作均需针对具体数据库获得人工许可。

1. 确认连接主机、端口、`DATABASE()`、Flyway 版本、代码提交；保存 `01_inventory.sql` 输出。停止应用及其他写入者。核对阅读全部文章，包括历史软删除记录。核对旧写作的消费者和物理外键、触发器。
2. 将备份放在仓库外或被忽略的本地私有目录，禁止提交账号数据、私稿、连接密码和 dump。示例：`mysqldump --single-transaction --hex-blob --routines --triggers --no-tablespaces --set-gtid-purged=OFF --result-file=<private-backup.sql> <approved-database>`。连接信息从现有私密配置读取；密码不放命令参数或日志。
3. 备份应含全部 schema、Flyway 历史及数据。生成 SHA-256 校验。由于 DDL 可能自动提交，数据库 dump 与可恢复验证是部署前置条件，不能依赖事务回滚 DDL。
4. 创建名字受控的隔离库，例如 `sr_english_retirement_restore_<timestamp>`，恢复 dump。禁止 dump 含 `CREATE DATABASE`/`USE` 指向原目标库；不得把连接凭据、私稿正文写入验收报告。逐表比较数量与全行摘要，尤其原创写作 owner、正文、状态、标签和历史版本。保存核对结果。
5. 在隔离库演练：替换 `03_reset_once.sql` 四个门禁参数（库名、`RESET_READING_ONCE:<库名>`、七表计数顺序串、按 ID 排序的 `id:row_version` 串），先验证错库/错计数不删数据及默认回滚恢复，再在隔离副本显式提交。结果应为七表归零，原创写作、词汇、语法、分类及非英语全部行摘要不变。
6. 已知当前阅读/写作未登记媒体或搜索文档，仍须每个目标环境重新核对。若出现依赖，用实际 `source_module/source_type/source_id` 或 `content_type/content_id` 确认来源，并补充单独审核的精确清理脚本；现有脚本不允许直接带依赖执行。绝不删除共享媒体二进制、词汇发音或语法附件。
7. 对备份、恢复结果、文章清单和预计删除数取得具体目标许可后，才可制作一次性执行副本。原脚本保持 `ROLLBACK`。执行副本必须有完整门禁并核对保护数据摘要；使用单一连接、无 `--force`，人工审阅后显式 `COMMIT`。记录操作者、批准消息、实际删除数、时间和目标；任何漂移先重新预检。
8. 执行 V2_037、启动对应应用，运行 `04_verify.sql` 及公开 API 检查。先验证归零且原 slug 不可访问，重启确认不回填；管理员后续新增的文章必须重启后仍保留。正式恢复需维护窗口：恢复整个一致性快照或审核的定向恢复，不可覆盖清空后新增内容。

V1 导入必须明确排除阅读及旧写作素材/题目，禁止通过旧迁移重跑、自动种子或启动清空来实现这次维护。现有 V2 运行代码没有此类英语回填；未来独立导入方案应单独审核。
