## event 与 dashboard 的位置

- `event` 保留为发布后派生数据同步的适配入口。跨模块事件类型位于发布模块的 `api/event`，监听器只把事件交给搜索或 SEO service。它不能简单并入 Controller 或 Mapper：源模块提交后需要通知其他模块，直接相互注入业务实现会增加耦合。SEO 教程快照成功提交后才安排通知入队。
- 搜索/SEO 消费失败沿用现有的记日志与重建恢复策略；目前没有持久化事件重试或失败告警。本轮没有改变这一语义。
- `dashboard` 保留为每个模块向站点概览提供数据的适配入口。`common/dashboard/api` 是共享契约，`site/service` 负责并发聚合、超时和降级，各模块 service 负责查询和业务汇总。教程源现只调用 service。
- dashboard 聚合现在对重复/空模块码启动失败，对空数据或不完整数据标记单模块降级，保留其他模块的结果。

## SEO 包结构补充整理

按后续验收反馈，`SeoHtmlRenderer` 已从 `service` 移至 `renderer`。它负责把 `SeoPageModel` 的 Markdown 正文转换为已转义的纯文本 HTML，并写入标题、描述和 canonical；`SeoSnapshotService` 将输出存入 SEO 快照，公开页面请求再附上前端构建资源。它不是前端 UI 组件。

SEO 的 `service` 根目录只保留业务接口，具体服务位于 `service/impl`，实现类统一以 `Impl` 结尾。五个内容来源实现位于 `provider/impl`，共享契约位于 `provider`；HTML 渲染、启动补建、IndexNow 发送和通知定时执行分别位于 `renderer`、`lifecycle`、`notifier`、`job`。canonical URL 解析位于 `config`，无状态元数据格式化位于 `utils`。跨模块 `api` 契约、路由和响应字段未改。

## 截图所示四个模块的再次整理

| 模块 | 调整 |
| --- | --- |
| SEO | `RobotsService.text()` 改为 `robotsTxt()`；Controller 继续以 `text/plain` 输出 robots.txt 字符串。`SeoNotificationService`、`SeoSnapshotService` 的接口与 `Impl` 分开，通知轮询放入 `job`；URL 解析与元数据格式化不再伪装成业务 Service。 |
| Media | 上传限流器移入 `security`。`MediaStorage` 保留为文件流读写契约，本地文件实现统一命名为 `LocalFileMediaStorageImpl`；契约参数与结果命名为 `MediaStorageWriteRequest`、`MediaStoredObject`。 |
| Analytics | 聚合业务改为 `AnalyticsAggregateService` + `Impl`，定时器移入 `job`，原始事件清理经 Service 进行，不再由任务直接调用 Mapper。提交限流器和来源分类器分别移入 `security`、`utils`。 |
| Account | 邮件业务改为 `AccountMailService` 接口与 `AccountMailServiceImpl` 实现，其他业务实现只注入接口。 |

`service` 用于业务边界，`storage` 用于可替换的字节存储边界；因此两个包都保留。`event` 和 `dashboard` 仍作为跨模块适配入口，模块间调用仍经各自的 `api` 契约。

根据再次验收反馈，Media 的 `storage` 根目录进一步收敛为 `MediaStorage` 接口，`storage/impl` 只放 `LocalFileMediaStorageImpl`。原来的 `MediaStorageWriteRequest` 仅包装流和扩展名，现由 `store(InputStream, String)` 直接表达；写入结果 `MediaStorageResultDTO` 放在 `dto`。这样 `storage` 表示文件基础设施契约，`dto` 表示层间传输数据，`service` 表示上传与资产业务。

本次整理后，Media 的存储及上传目标测试通过，后端完整构建和前端生产构建通过，`git diff --check` 通过。MySQL 已由用户启动；运行中的后端成功连接数据库并校验 22 个迁移，前端首页、Vite API 代理与 `/robots.txt` 均返回 HTTP 200。此前因 MySQL 停止而失败的完整真库测试尚未在本次启动后重跑。
