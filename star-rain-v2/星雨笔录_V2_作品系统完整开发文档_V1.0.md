# 星雨笔录 V2 · 作品系统完整开发文档

> 版本：V1.0  
> 适用项目：星雨笔录 V2  
> 模块：作品 / Works  
> 目标：建立一个能够长期承载「软件、AI/Agent、工具、实验、内容创作」的通用作品系统，而不是只服务于程序员项目展示。

---

## 0. 文档结论

作品系统采用：

> **统一作品模型 + 作品分类 + 作品形态 + 标签体系 + 模板系统 + Block 区块系统**

核心原则：

1. **统一的是作品生命周期，不统一作品内容。**
2. 所有作品共享一个基本叙事骨架：
   - 起点 Origin
   - 目标 Goal
   - 过程 Process
   - 成果 Result
   - 复盘 Reflection
3. 不同类型作品使用不同模板：
   - 软件项目
   - AI / Agent
   - 工具
   - 实验
   - 内容创作
4. 模板不是固定页面，而是**预生成的一组可编辑 Block**。
5. 前台详情页由 Block 动态渲染，后台支持新增、隐藏、排序和编辑 Block。
6. 图片、视频、附件等媒体文件统一走 OSS，数据库仅保存元数据和 URL。
7. 项目状态与发布状态必须分离。

---

# 1. 产品定位

## 1.1 模块定位

“作品”模块不是普通项目列表，也不是博客文章集合，而是：

> **星雨笔录中的个人创造档案馆 / Portfolio + Case Study + Creation Archive**

它需要同时承载：

- 软件产品
- Web / Desktop / Mobile 项目
- AI / Agent 项目
- CLI / 自动化工具
- 技术实验 / PoC
- 视频
- 音乐
- 写作
- 小说
- 摄影
- 设计
- 动画
- 后续可能出现的机器人、游戏、科研实验等

---

## 1.2 设计目标

### 用户侧目标

用户进入作品页后，应能快速回答：

- 这个作品是什么？
- 为什么做？
- 做成了什么？
- 过程如何？
- 有什么成果？
- 作者从中学到了什么？
- 是否可以在线体验、查看源码或查看成品？

### 作者侧目标

后台应支持：

- 快速创建作品
- 从模板开始
- 灵活增删模块
- 不需要每次新增作品类型都改数据库
- 可以长期迭代
- 能沉淀项目开发过程和创作过程

# 27. 最终定位

作品系统最终应成为：

> **星雨笔录中记录“我创造过什么、为什么创造、如何创造、最后创造出了什么”的长期个人档案系统。**

它不属于某一种技术栈，也不局限于软件工程。

未来无论是：

- 软件
- Agent
- 游戏
- 音乐
- 小说
- 视频
- 科研实验
- 机器人
- 创业产品

都应该能够进入同一个“作品系统”，只是选择不同模板、组合不同 Block。

# 28. 最终架构摘要

```text
作品 Work
│
├── 分类 Category
├── 形态 Format
├── 标签 Tag
├── 状态 Status
├── 媒体 Media
├── 链接 Link
└── Sections
     │
     ├── Text
     ├── Markdown
     ├── Image
     ├── Gallery
     ├── Video
     ├── Audio
     ├── Code
     ├── Timeline
     ├── Architecture
     ├── Stats
     └── Custom

模板 Template
│
└── Template Sections
      ↓
创建作品时复制
      ↓
生成 Work Sections
      ↓
作者自由编辑
```

这就是星雨笔录 V2 作品系统的最终核心模型。
